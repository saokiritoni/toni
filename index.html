AI 광고 분석 대화 서비스

개요

마케터가 자연어 대화로 광고 데이터를 분석하는 B2B AI 서비스입니다. 실사용자를 받는 프로덕션 서비스인 만큼 인증·보안·운영 관측성 같은 서비스의 신뢰 기반을 백엔드에서 설계·구현했고, 그 위에서 프론트엔드 전반도 함께 개발했습니다.

Tech

KotlinSpring BootPostgreSQLDynamoDBReactTypeScript

진행한 일 · Backend

1. 인증 시스템 직접 구현
  • Google/Naver 소셜 로그인부터 JWT 발급까지, 인증 전 과정을 라이브러리에 위임하지 않고 직접 설계·구현
  • Shadow Login: 운영자가 사용자의 화면 그대로 들어가 문의를 처리하는 기능. 모든 활동이 "누가(운영자) 누구로(사용자)" 했는지 감사 기록에 남도록 설계
  • 동시 로그인 차단, 일정 시간 미사용 시 자동 로그아웃, "다른 기기에서 로그인됨" 안내 등 세션 정책 구현
2. 비정상 접근 자동 차단
  • 로그인 실패나 위조된 토큰을 반복해서 보내는 IP를 자동으로 차단하는 방어 계층 구현
  • 차단 시스템에 장애가 나도 서비스는 멈추지 않도록 설계. "보안 기능의 장애가 정상 사용자를 막아선 안 된다"는 우선순위를 명시적으로 선택하고 문서화
  • 운영자가 잘못 차단된 IP를 즉시 풀 수 있는 관리 API 제공. 누가 언제 해제했는지 기록
3. 권한 체계 (RBAC)
  • 허용 목록에 없는 API는 기본 차단. 새 기능을 추가하다 권한 설정을 빠뜨려도 실수로 열리는 사고가 구조적으로 불가능하게 설계
  • 운영자 권한자가 동시에 전부 사라지는 엣지 케이스(서로를 동시에 강등)를 DB 락으로 차단
4. 운영 알림 체계 설계 (PostgreSQL 기반)
  • 장애가 나면 협업 메신저로 즉시 알림. 같은 에러가 수만 건 터져도 상세 1건 + 요약 1건으로 수렴하는 폭주 방어 설계
  • 별도 메시지 브로커 없이 PostgreSQL만으로 구현: 여러 서버가 에러 카운트를 같은 행에 원자적으로 합산하고, 발송 상태를 DB에 두어 재시작·배포에도 유실 없음
  • 발송 담당 서버 1대를 PostgreSQL 행 잠금(FOR UPDATE SKIP LOCKED)으로 선출: 중복 발송을 제거하고, 담당 서버가 죽으면 다른 서버가 자동 승계
  • 집계·발송·상태 갱신을 하나의 트랜잭션으로 묶어 정합성 보장, 집계 쿼리는 부분 인덱스로 최적화
  • "알림 시스템 자체가 조용히 멈추면 누가 아는가"까지 설계. 외부 감시(CloudWatch)가 알림 루프의 생존을 감시하는 이중 구조
5. 감사로그 · 컴플라이언스
  • 누가 무엇을 언제 바꿨는지 자동으로 남는 감사로그 체계 구축. 개인정보는 로그에서 마스킹, 요청 흐름은 전 구간 추적 가능

진행한 일 · Frontend

1. 화면 데이터 갱신(캐시) 전략 설계
  • 화면 데이터가 낡는 두 경우, 내가 바꾼 것과 서버가 뒤에서 바꾼 것을 구분해 각각 다른 갱신 전략을 세우고 팀 표준으로 문서화
  • 목록에 이전 행이 남아 보이는 테이블 버그를 분석한 결과, 행 키(rowKey) 중복 탓에 React가 바뀐 행을 다시 그리지 못한 것이 원인. 1:N 펼침 목록의 행 고유 키 규칙을 세워 해결하고 재발 방지 규칙으로 문서화
2. 로딩 UX 설계
  • 빠른 응답에서 로딩 표시가 한 프레임 깜빡이고 사라지는 문제를 지연 게이트로 제거. 짧으면 바로 콘텐츠, 길면 스켈레톤
  • 준비된 영역부터 순차적으로 보여주는 점진 노출 설계로 화면 흔들림(레이아웃 시프트) 제거

개요

'방대한 광고 데이터를 사람이 직접 조작해야 한다'는 페인 포인트에서 출발해, 자연어로 광고 데이터를 분석하는 서비스를 만들었습니다. 이를 위해 13개 AWS 서비스를 조합한 서버리스 아키텍처를 2주 안에 단독으로 설계·구축했습니다.

  • Why마케터가 raw 데이터를 직접 조작, 반복되는 엑셀 리포트 수작업
  • HowAWS 서버리스 파이프라인 + Bedrock(Claude) Tool-Use
  • Result자연어 질문 → AI가 직접 쿼리 작성·조회, 인프라 비용 83% 절감 설계

아키텍처 (AWS)

  • 데이터 수집 파이프라인: 광고 API(Kakao·Google)의 일별 성과를 서버 없이 자동 수집(EventBridge → SQS → Lambda → S3). 일부가 실패해도 전체가 멈추지 않는 큐 기반 구조
  • AI 분석: 자연어 질문을 받으면 AI(Bedrock)가 직접 SQL을 만들어 데이터 레이크(Athena)를 조회하고 자연어로 답변
  • 캐싱: Redis 캐싱으로 대시보드 응답 시간 99.58% 감소
  • 리포트 공유: 매주 자동 생성되는 리포트를 로그인 없이 볼 수 있는 읽기 전용 링크로 공유, Excel 다운로드 지원
